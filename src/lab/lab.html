01 / SSH KEY PAIR

Generate an SSH key pair.

A new generation replaces the current pair. Download the private key before starting another pair.

PRIVATE KEY

The private key is exported directly to a file and is never displayed on the page.

Keep the passphrase separately from the private key.

Which file goes where?

The public .pub file goes to the server or service account. The private file stays on the computer used to connect. Both files belong to the same fingerprint.

For SSH, choose OpenSSH for both files. Place them in the SSH directory, restrict the private file and install only the public key on an authorized server. Replace USER@HOST with the intended account and host.

    Generation and privacy details
    
Key pairs, secrets, TOTP setups and artwork each ask for a fresh sample from the shared camera, server and browser source. Browser cryptographic randomness is added. Ed25519 derives its pair from mixed bytes; RSA prime candidates use the same byte provider. Public or repeated camera images do not replace local cryptographic randomness, and no physical entropy rate has been established for the cameras. The ASCII artwork comes from an independent sample and never displays a key's private seed.

    
There are no analytics or persistent browser storage in this workspace. The SSH QR contains the public key. Secret and TOTP QR codes contain their labeled secret values and transfer them when scanned. Private SSH keys download as files. Clear removes displayed values and releases session references; downloaded files and clipboard contents remain under browser and operating-system control. JavaScript cannot guarantee removal of every memory copy. The portable download includes all four tools and makes only a credential-free request for the shared public sample.
